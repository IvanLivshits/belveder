# Сначала переиспользуй

## Алгоритм

1. **Найди.** `grep -rn "<ключевое слово>" packages/ apps/` и посмотри `packages/*/src/index.ts`: каждый пакет экспортирует всё публичное из index.
2. **Расширь.** Если похожее есть, добавь параметр или проп, а не копию. Лучше одна функция с опцией, чем две почти одинаковых.
3. **Создай.** Только если ничего не подошло. Положи в самый нижний слой, где это можно протестировать (см. `architecture-guardrails`).

## Где искать типичные вещи

| Нужно | Уже есть |
|---|---|
| Проверить условие на качество | `engine/conditions.ts: evaluate()` |
| Применить эффект | `engine/effects.ts: applyEffects()` |
| Выбрать сторилет для локации | `engine/select.ts: selectStorylet()` |
| Детерминированный рандом | `engine/rng.ts` |
| Собрать отчёт за ночь | `engine/report.ts: buildReport()`, для рендера `step.ts: currentReport()` |
| Данные для экрана сцены | `engine/step.ts: currentScene()` (реплики, выборы со скрепкой, двери, этажи лестницы) |
| Реплики карточки или ответа, лента места | `engine/lines.ts: sceneLines()`, `replyLines()`, `openFeed()`, `extendFeed()` |
| Слух этой ночи | `engine/rumors.ts: currentRumor()` |
| Зацепки, скрепки, поручители | `engine/leads.ts: leadsView()`, `leadTargets()`, `vouchersView()` |
| Этажи лестницы с ценой и замками | `engine/stairs.ts: stairsView()`; сам переход — `step.ts: travel()` |
| Сериализовать состояние / профиль | `engine/storage.ts` (кодек, чанки) + `apps/miniapp/src/storage.ts` (транспорт KV) |
| Загрузить контент из YAML | `validator/load.ts: loadWorldDir()` |
| Фон с дождём, карточка сцены с лентой, список выборов, три двери, сетка этажей, HUD качеств, блокнот с вкладками, страница отчёта, титул | `ui-kit` |
| Telegram API | `apps/miniapp/src/telegram.ts` — единственное место |
| Схема любой сущности контента | `content-schema` |

## Правило двух использований

Выносить в пакет нужно, когда код понадобился **второй** раз, а не заранее. Пока одно использование — пусть живёт на месте.
Исключение: всё, что относится к правилам игры, сразу идёт в engine, даже если используется один раз.

## Как не переабстрагировать

- Не делай интерфейс с одной реализацией. Функция и объект достаточны.
- Не добавляй опции «на будущее». Нужно будет — добавишь.
- Не делай generic там, где два конкретных типа читаются лучше.
- Если абстракция требует объяснения в комментарии дольше трёх строк — она лишняя.
- Удаляй код, который перестал использоваться, вместе с изменением.
