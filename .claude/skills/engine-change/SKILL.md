# Изменение движка

## Принципы

- Всё в engine — чистые функции: `step(state, action, world) -> state`. Ни одной мутации входа, ни одного побочного эффекта.
- Рандом только через `rng.ts` (mulberry32): состояние RNG лежит в `state.rng`, каждое использование возвращает новое значение. Одинаковый seed + одинаковые действия = одинаковое состояние, байт в байт.
- Движок не знает о мире: имена качеств, локаций, сторилетов приходят из `world`. Глобальные правила (`onChoice`, `nightEndWhen`) — тоже данные из `world.rules`.
- Нет `Date`, `Math.random`, `console`, `fetch`, `window`.

## Тесты

Главный вид тестов — сценарные прогоны в `packages/engine/test/`:

1. Сценарий = seed + список действий + мир (реальный `content/belvedere` или мини-мир внутри теста).
2. Прогон даёт финальный state и лог. Digest = sha256 от канонической сериализации (ключи отсортированы, см. `engine/digest.ts`).
3. Ожидаемый digest лежит в `test/golden/*.json`. Тест падает, если digest изменился.

Мелкие юнит-тесты пишем только для нетривиальных функций (парсер условий, кодек storage).

## Когда digest меняется

Digest обязан измениться только если изменилось **поведение**. Порядок действий:

1. Убедись, что изменение поведения намеренное. Если нет — это баг, чини.
2. Запусти `bun test` и посмотри, какие сценарии упали. Проверь diff лога, а не только хеш: `UPDATE_GOLDEN=1 bun test` перезапишет golden-файлы, `git diff test/golden` покажет, что именно поменялось.
3. В коммите объясни: «golden: <сценарий> изменился, потому что …». Коммит без объяснения с обновлённым golden — ошибка ревью.
4. Изменение контента тоже может менять digest сценариев на реальном мире — это нормально, но объяснение всё равно нужно.

## Чек-лист

- [ ] Новая функция принимает всё через аргументы и ничего не читает снаружи?
- [ ] Новый рандом идёт через `rng`?
- [ ] Схема состояния поменялась → поднял `STATE_VERSION` в `engine/storage.ts` и добавил миграцию или сброс?
- [ ] Добавил или расширил сценарный тест?
- [ ] Golden обновлён осознанно и объяснён в коммите?
