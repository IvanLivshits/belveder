# Архитектура

Монорепо на Bun workspaces. Игра = чистый движок, который исполняет мир-как-данные; всё остальное — тонкие адаптеры.

## Слои

```
apps/miniapp ─┐
apps/bot     ─┼─▶ packages/ui-kit ─▶ packages/engine ─▶ packages/content-schema
packages/validator ───────────────▶ engine + content-schema
content/belvedere  (данные: YAML → build/world.json, загружается как JSON)
assets/            (WebP + assets.json, картинки только по id)
```

Стрелка = «может импортировать». Обратно нельзя. Подробно: `.claude/skills/architecture-guardrails`.

## Движок (`packages/engine`)

Чистые функции над неизменяемым состоянием. Ни I/O, ни DOM, ни Telegram, ни знания о мире.

```
GameState { seed, rng, phase: scene|outcome|report|ending, location, storyletId, pendingChoice, run{}, profile{}, log[], report{}, history{}, ending }

newNight(profile, world, seed)  → state   # rules.migrations → rules.onNightStart → слух дня → первый сторилет в rules.start
choose(state, world, index)     → state   # эффекты выбора → rules.onChoice (если не free) → resolve;
                                          # есть reply/outcome и ход уводит из локации или кончает ночь ? фаза outcome
continueOutcome(state, world)   → state   # resolve: endNight ? отчёт : первый interrupt.goto ?? goto выбора ?? «дальше»
travel(state, world, floor)     → state   # лестница: этаж, цена в ходах, stairs.onTravel → interrupts → встреча по пути ?? площадка
pledge(state, world, pairId)    → state   # fake = 0, pledged.<id> = 1; returnWhen ? real = 1, returned.<id> = 1, memories_returned += 1; отчёт
currentScene(state, world)      → { storylet, lines[], choices[{index, mode: say|do|plain, text, available, lead}], doors[], memories[], stairs }
currentOutcome(state, world)    → { storylet, lines[] }   # реплики ответа, пока фаза outcome
openFeed(state, world)          → { location, entries[] } # лента места: реплики карточки (+ выбор и ответ в фазе outcome)
extendFeed(feed, prev, next, w) → feed     # лента после действия: выбор игрока, ответ, реплики сменившей карточки; новое место — новая лента
stairsView(state, world)        → { current, floors[{floor, location, label, cost, locked, lead}], back }
currentRumor(state, world)      → Rumor | undefined   # слух этой ночи (run-флаг rumor.<id>)
leadsView(state, world)         → { open[], closed[], total, done }   # зацепки блокнота
progressNotes(state, world)     → string[]   # report.progress с истинными when; {leads_done}, {leads_total} считает движок
isResumable(state, world)       → boolean    # карточка сохранённого забега ещё существует (после обновления контента)
currentReport(state, world)     → [{ slot, label, fragment, text }]
currentNotes(state, world)      → string[]   # report.notes с истинными when
morningNotes(state, world)      → string[]   # morning.notes, по состоянию отчёта (run-флаги ещё стоят)
pledgeOptions(state, world)     → [{ id, label, canReturn }]   # canReturn: returnWhen выполнено прямо сейчас
choiceCost(state, world, choice)→ number     # прирост «часов» (качество из rules.onChoice) от эффектов + onChoice; free → 0
changedQualities(prev, next)    → string[]   # что изменилось между состояниями; приложение показывает hint при первом изменении
notebookView(state, world)      → { pages[], locked, life{lines[{pair, status: fake|empty|real, text}]}, leads, vouchers{title, lines[], footer} | null }
evidenceView(state, world)      → { items[{id, title, image, text, tonight}], locked }   # папка улик: найденные карточки по `order`
clockTime(state, world)         → "23:30" | null   # rules.clock: start + качество × step минут
endingView(state, world)        → { id, title, image, paragraphs[], epilogues[] }   # phase === "ending"
storyView(profile, world, id)   → { title, sections[] }   # «Дело Хейла» из истории ночей профиля
newCase(profile)                → Profile   # только endings.*, история пустая
```

Тексты проходят через `renderText`: `{quality_id}` заменяется значением из состояния.

- **Качества** — целые числа в двух мешках: `run` (сбрасывается каждую ночь) и `profile` (живёт между ночами). Флаги и множества — тоже качества 0/1 с составным id (`visited.floor2.tenant`), объявленные через namespace `visited.*`. Значение, равное default, не хранится.
- **Выбор сторилета**: все сторилеты локации с истинными `when`, берутся с максимальным `priority`, ничья решается seed-RNG (mulberry32, состояние в `state.rng`).
- **Глобальные правила** из `world.rules`: `onChoice` (эффекты на каждый выбор, например `turn += 1`), `interrupts` (список `{when, goto}`, первый подходящий после каждого выбора переносит игрока), `onNightEnd` (эффекты на профиль). Ночь заканчивается только `endNight`-выбором или залогом воспоминания, поэтому рассвет и поимка — перехваты в локацию залога. Движок исполняет всё это, не зная смысла.
- **Воспоминания**: `world.memories` — список пар `{id, fake, real, returnWhen}`. Флаги для движка непрозрачные id качеств. При залоге пары движок пишет run-флаги `pledged.<id>`, `returned.<id>`, `returned_tonight` и профильный `memories_returned` (константы `RESERVED_QUALITIES`), чтобы отчёт знал, что случилось этой ночью. Сторилет `layout: pledge` показывает ложные воспоминания со значением 1; залог ночи целиком — обычный выбор с эффектом из контента.
- **Реплики и лента**: карточка говорит списком `lines` (`who` из `world.speakers`, свой `when` у строки, `rumor: true` — текст слуха дня голосом говорящего), выбор подписан `say` (реплика Ника), `do` (действие) или `text`, после него идёт `reply`. Старые `text` и `outcome` движок отдаёт теми же строками: абзац = реплика рассказчика без `who`. Лента места (`Feed`) — чистая функция от пары состояний: пока игрок в той же локации, в неё падают его выбор, ответ и реплики сменившей карточки; в новой локации лента начинается заново. Ответ, после которого игрок остаётся на месте, хода не останавливает; фаза `outcome` («Дальше») осталась только там, где ответ иначе не успеть прочитать: выбор уводит в другую локацию или кончает ночь.
- **Слух дня**: `world.rumors` (из `rumors.yaml`). В начале ночи движок ставит run-флаг `rumor.<id> = 1` (`RESERVED_QUALITIES.rumorPrefix`): в первую ночь (счётчик ночей 0) это `rules.firstNightRumor`, дальше случайный по seed ночи из слухов с истинным `when`, кроме слуха прошлой ночи (он записан в `NightRecord.rumor`). Что слух меняет, решает контент условиями на флаг.
- **Зацепки и поручительства**: `notebook.leads` — открытые вопросы дела (`when` — появилась, `done` — закрыта, оба по profile-качествам; `target` — локация, куда ведёт). Выбор с `goto` в `target` открытой зацепки несёт `lead` (скрепка), на лестнице скрепка у этажа, с площадки которого есть такой выбор. `notebook.vouchers` — страница поручителей: движок после каждой пачки эффектов дописывает в `history.vouchers` качества из `names`, ставшие 1, и страница показывает имена в этом порядке.
- **Лестница**: `world.stairs { location, quality, floors, costMods, locks, events, onTravel }`. Сторилет `layout: stairs` задаёт только текст, этажи рисует движок (`stairsView`). `travel`: этаж = цель, часы += `ceil(|куда − откуда| / 2)` (не меньше 1) + подошедшие `costMods` вместо обычного хода, затем `onTravel`, перехваты, и не больше одной встречи — сторилета локации `stairs.events`, чьи `floors: [от, до]` пересекают путь (этажи после текущего до целевого включительно; без `floors` — где угодно), по `priority`. Выбор встречи без `goto` ведёт дальше, на площадку целевого этажа. Этаж из `locks` закрыт, пока не выполнена ни одна группа `open_any`.
- **Начало ночи**: `rules.migrations` (список `{when, effects}`: все `when` проверяются по профилю, с которым пришла ночь, потом применяются эффекты подошедших; так сохранения до v2 получают знания и зацепки; миграции проверяются каждую ночь, поэтому профиль несёт `content_version`, и строки для старых сохранений смотрят на него), затем `rules.onNightStart` (эффекты на свежий run: вещи Хейла на столе), затем слух.
- **Улики**: `world.evidence.items` — карточки `{id, order, flag, image, title, text}`, где `flag` — run-качество. После каждого выбора движок ставит профильный `found.<id> = 1` для каждой карточки с `flag == 1` (`RESERVED_QUALITIES.foundPrefix`), так папка помнит находки всех ночей; `tonight` в `evidenceView` — это `flag == 1` прямо сейчас.
- **Концовки**: выбор с `ending: <id>` (из `endings.yaml`) после `outcome` завершает игру: движок ставит профильный `endings.<id> = 1` и run-флаг `ending_night = 1` (фрагменты отчёта финальной ночи), закрывает ночь как обычно (отчёт, `onNightEnd`, запись в историю) и переводит состояние в фазу `ending`. Приложение показывает экран концовки, затем рассказ, затем «Новое дело» (`newCase`: из профиля остаются только `endings.*`, по ним эпилоги следующих концовок узнают прошлые прохождения).
- **История ночей**: `state.history` переезжает из профиля в ночь и обратно. На каждом конце ночи движок дописывает `NightRecord { night, pledged, pair?, report, values }`: реальный номер ночи (счётчик из `rules.onNightEnd` плюс один, `nightQuality`; так старые сохранения без истории не начинают с «Ночь 1»), заложена ли ночь целиком (`rules.pledgedNightWhen` по состоянию отчёта), какая пара заложена, id фрагментов по слотам и значения плейсхолдеров этих фрагментов на момент отчёта (чтобы страница рассказа не показывала сегодняшние числа). Отдельно список `pledges` — пары по порядку залога. `storyView` собирает части из `endings.yaml → story.parts`: `opening` (первый слот первой ночи), `nights` (незаложенные ночи сплошной прозой: абзац на слот без подписей, первая ночь без слота `opening`, ночи с заложенной парой без слота литании), `pledged_note`, `litany` (тексты последнего слота тех ночей, где заложена пара, одним абзацем), `ending`, `epilogues`; `closing` всегда в конце.
- **Часы**: `rules.clock { quality, start, step }` — только отображение (`clockTime`); цена хода по-прежнему из `rules.onChoice` (`clockQuality`, `choiceCost`).
- **Отчёт**: для каждого слота берётся фрагмент с истинными `when` и максимальным приоритетом; ничья через RNG. Считается до сброса run, поэтому может ссылаться на run-качества.
- **Детерминизм**: одинаковый seed + действия → байт-в-байт одинаковое состояние. Проверяется golden digest = sha256 от канонического JSON.

## Контент (`content/belvedere`)

`world.yaml` (качества с необязательным `hint`, локации, правила, слоты, `notes` и `progress` отчёта, `speakers`, `stairs`) + `storylets/*.yaml` + `report-fragments/*.yaml` + `notebook.yaml` (страницы-справочник с `when` только по profile-качествам, шаблоны страницы «Что я о себе знаю», зацепки `leads` и страница поручителей `vouchers`) + `evidence.yaml` (карточки папки улик) + `endings.yaml` (концовки с эпилогами и сборка рассказа «Дело Хейла») + `rumors.yaml` (слухи дня). Первая ночь (`nights == 0`) — обучение: правила объясняют персонажи в карточках `storylets/00-first-night.yaml`. Весь дом написан репликами (цикл ночи v2; с v15 — и этажи 5–12, подвал, тринадцатый); старый формат `text`/`outcome` движок по-прежнему понимает и рисует той же лентой. Условия и эффекты — строки `quality op int`, валидируются regex-ом в zod и парсятся движком. Формат: `.claude/skills/storylet-authoring`.

Сборка `bun run content:build` → `build/world.json` (не коммитится). Валидируется дважды: validator при сборке (CI) и zod при загрузке в приложении.

## Сохранение

Кодек в `engine/storage.ts` (чистый, тестируется без браузера): компактный текст `b1;q.<id>=<n>;…`, только ненулевые качества, разбиение на чанки ≤ 4000 символов с заголовком `<version>:<count>|`. История ночей едет в профиле полями `h=` (ночь: `<0|1>/<пара>/<слот:фрагмент+…>/<качество:значение+…>/<номер ночи>[/<слух>]`, ночи через запятую), `pl=` (пары по порядку) и `vo=` (качества поручителей по порядку); у забега поле `end=`, переход по лестнице в логе пишется как `<сторилет>:f<этаж>`. Поля необязательные: документы до появления рассказа, слухов и поручителей читаются с пустыми значениями, версия формата не менялась. Забег, сохранённый на карточке, которой в новом контенте уже нет, приложение не продолжает (`isResumable`): ночь пропадает, профиль остаётся.

Транспорт в `apps/miniapp/src/storage.ts`: два хранилища, localStorage всегда и Telegram CloudStorage внутри Telegram (ключи `profile_N`, `run_N`, `ui_N`). Документ `ui` — что интерфейс уже показал: подсказки качеств (`hintsShown`), прочитанные страницы блокнота (`pagesRead`), открытые карточки улик (`evidenceSeen`) и увиденные зацепки (`leadsSeen`); это не качества мира, движок о них не знает. Его множества только растут, поэтому две копии не ранжируются по `rev`, а объединяются (G-Set, `rev = max + 1`): так чтения с телефона и десктопа не теряют друг друга. Сброс прогресса (`resetAll`) пишет tombstone профилю и забегу и поднимает `epoch` документа `ui`: копия с большей эпохой заменяет старую, не объединяясь. Вызывается из Telegram `SettingsButton` или из ссылки внизу блокнота. Документ обёрнут в конверт `rev=<n>;at=<ms>|…`, где `rev` монотонно растёт при каждой записи. Запись fire-and-forget: локально сразу, в облако через очередь с одной записью в полёте и схлопыванием до последней версии. Ошибки облака глотаются, интерфейс их не ждёт. Чтение берёт копию с бóльшим `rev` (при равенстве облачную) и досинхронизирует отставшую сторону, если та читалась. Удаление run — tombstone с пустым телом.

После каждого выбора сохраняются и run (seed, позиция RNG, локация, лог), и profile. После отчёта run удаляется. На титуле при наличии run — «Продолжить ночь».

## Mini App (`apps/miniapp`)

Экраны: титул → ночь (сцена-лента / блокнот с вкладками «Зацепки» и «Блокнот» / папка улик: список карточек, карточка с фото и заметкой) → отчёт (под ним строки прогресса дела) → утро; выбор с `ending` сначала спрашивает подтверждение прямо в игре (`ConfirmSheet`), затем последствие → экран концовки (`EndingPage`, картинка 9:16) → «Дело Хейла» (`StoryPage`, одна длинная бумажная страница) → «Новое дело». Остальное: отчёт → утро («Что я о себе знаю» с анимацией изменений этой ночи, строится из состояния отчёта до сброса run) → следующая ночь.

`telegram.ts` — единственное место с `window.Telegram.WebApp`. `content.ts` — загрузка и zod-валидация `world.json` и `assets.json`. `App.tsx` — экраны title / night (scene или report), вызовы engine, сохранение. В HUD часы (`clockTime`) вместо номера хода, с «Ход 3/16» подписью; иконки блокнота и папки улик с точкой на непрочитанном (новая зацепка тоже ставит точку на блокнот) и иконка слуха дня: по тапу его текст показывается подсказкой. Рендер — компоненты `ui-kit`. Фон 9:16 через `Backdrop`: портрет-сцена (h > w в `assets.json`) заменяет фон, квадратная улика ложится вставкой-фотокарточкой поверх фона. Нижняя панель — `SceneCard`: лента реплик появляется по одной (пауза зависит от длины строки, тап показывает всё сразу), старые реплики места остаются выше и прокручиваются; под лентой `ChoiceList` (реплика Ника «— …», действие «[…]», справа цена и скрепка), `DoorPicker`, `PledgePicker` или `StairsPicker` (сетка этажей с ценой, замком и скрепкой). Саму ленту (`Feed`) и сколько её строк уже показано хранит приложение; после перезагрузки лента места начинается с текущей карточки.

## Бот (`apps/bot`)

grammY на вебхуке через `Bun.serve`. `/start` → кнопка `web_app`. `set-webhook.ts` ставит вебхук с секретом.

## Проверки

- `bun test` — сценарные прогоны с golden digest (engine на мини-мире и на «башне» `test/tower-world.ts` для цикла v2, validator на реальном мире), тесты кодека и правил. Каждое изменение хеша — строка в `docs/golden-changelog.md`.
- `bun run validate` — правила контента + симуляция случайных ночей (тупики = ошибка).
- `bun run typecheck` — `tsc -b` по project references.

## Что архитектура допускает, но MVP не делает

Другой рендер того же мира (сайт, устройство): нужен только новый адаптер уровня `apps/*`. Чужие миры (UGC): `world.json` самодостаточен, схема в `content-schema`. См. `docs/backlog.md`.
